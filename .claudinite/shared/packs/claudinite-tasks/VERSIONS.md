| 60830.5 | 2026-08-30 | The auto-merge decision becomes a policy: `expected_outcome` collapses to `none`/`pr` (legacy spellings normalize at the door, advisory rename at author time) and a `pr` task declares `automerge` — `nothing`, `anything`, or a list of built-in diff classes `merge-policy.mjs` measures the actual diff against (a pack may extend them as `merge-rules.json` data; anything unresolved fails closed). Landing procedure lives only in `deliver-pr.md` — a task.md describes the changes to perform, never what happens to them. `usage-fold` stops maintaining the `merge=ours` `.gitattributes` line in-run: the pack seeds it at adoption (`seedOps`) and the advisory `generated-merge-driver` drives any repo whose own file predates that. A landing run stamps the `Claudinite-Automerge-Policy:` trailer and the new blocking `automerge-policy-scope` work check re-measures the verdict; the request lane's `Merge:` field now carries any policy expression, `if-narrow` resolving to the `narrow-diff` composite (#1459). |

The verdict survives as the human-facing instruction in the comment. Janitor rules E and F close a park once a later run of the same task converges clean, or once its task is no longer carried at HEAD — the verdict #1446 gave the executor, applied to the parked set it never picks (#1452). |
